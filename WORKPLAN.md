## Urteil Tribunal P2/P3 (2026-08-29) – verbindlich für die Implementierung

**export-sources.ts:** `.autoOrient()` vor Resize; 2560 lange Kante `fit: inside, withoutEnlargement`, lanczos3; JPEG **q95, chromaSubsampling 4:4:4**, mozjpeg (4:2:0 kostet bis 2,4 dB – der eigentliche Fehler im Plan); `.withIccProfile('srgb')` nur auf der Web-Quelle (selbstbeschreibendes Archiv), sonst keine Metadaten; EXIF (DateTimeOriginal in UTC formatieren, Make/Model, LensModel) mit `exif-reader` vor dem Strippen lesen; YAML nie überschreiben; Mapping Original→Slug/Titel/Tags aus einer JSON; `orientation`/`year` aus photos.json NICHT übernehmen (Pixel bzw. EXIF sind die Wahrheit).
**build-images.ts:** Breiten 480/960/1600/2560 **+ native Quellbreite bei Hochformat >1600** (z. B. 1707); tatsächlich erzeugte Breiten pro Foto ins Manifest (srcset nie aus der Konstante). Pro Breite EINMAL resizen (raw), daraus AVIF/WebP/JPEG. AVIF: effort 3, 4:4:4, **bitdepth 10**, Q-Leiter 60/57/54/52 + Budget-Clamp (−5 bis min 38; Budget KB 20/48/95/190, bei Hochformat nach Pixelzahl skaliert). WebP: effort 5, smartSubsample, Q 76/75/74/72 + Clamp ×1,35. JPEG-Fallback **960 und 1600**, q82 4:4:4 mozjpeg progressive. Sharpen je Breite (480/960: σ0.6 m1 0.3 m2 1.6; 1600: σ0.5 m1 0.2 m2 1.2; Maximalstufe: KEIN Sharpen). Kein toColorspace/keepMetadata/withMetadata – libvips-Default ist korrekt; Regressionstest: Rot 255,0,0 bleibt 255,0,0. OG-Bild `og.jpg` 1200×630 `fit: cover, position: attention`, q80. LQIP: WebP 20 px q35 Base64 + Durchschnittsfarbe Hex. S/W: keine Sonderbehandlung.
**Manifest:** zwei Artefakte, beide gitignored: `photos.manifest.json` (Root, vollständig, Build-Zeit) und `app/data/photos.index.json` (Client: slug, title, date, year, tags, collection, camera, lens, featured, hero, order, width, height, aspectRatio, orientation, color, lqip, `variants: {avif: number[], webp: number[], jpeg: number[]}` als Breitenlisten, URL per Konvention `/img/<slug>/<w>.<ext>`, `og: '/img/<slug>/og.jpg'`). Manifest-Kopf: schema 1, generatedAt, sourceMode content|demo, heroSlug (aufgelöst). Sortierung date desc, slug asc. `order` nur für die Startseiten-Kuration. Tags als zod-enum (tiere, natur, landschaft, segeln, schwarzweiss); Labels/Reihenfolge im Frontend (`shared/constants/tags.ts`). hero: 0 → Warnung + Fallback (neuestes featured, sonst neuestes), ≥2 → Fehler. Typen in `shared/types/photo.ts` (nur Typen), zod in `scripts/lib/schema.ts` mit bidirektionaler Typ-Klammer.
**Infrastruktur:** `scripts/lib/` (args, paths mit assertInside, slug, exif, schema, meta, variants, cache, manifest, report) + dünne CLIs. Cache `.image-cache/manifest-cache.json` mit settingsHash (RENDER + sharp.versions.vips) und pro Eintrag sourceHash/mtime-Fastpath/metaHash (YAML-Änderung ⇒ kein Re-Encode). Orphan-Cleanup nur unter `public/img`, Slug-/Datei-Allowlist, Abbruch bei 0 Quellen, `--dry-run`. Issues sammeln, `process.exitCode`, ERROR/WARN-Tabelle, `--strict`. Flags: --dry-run --force --only --strict --source-dir (kein --out-dir für build-images). Node 24 nativer TS-Strip: `node scripts/x.ts`, **tsx streichen**, engines >=24, `tsconfig.scripts.json` mit erasableSyntaxOnly; parseArgs/styleText statt commander/chalk. Sequenziell (libvips parallelisiert intern), `mapLimit` als Modul ohne Einsatz. vitest mit 5 Tests (slug, schema, manifest, cache, paths). GitHub Actions CI **ohne** Submodule (beweist Demo-Fallback). Deps: sharp, zod, yaml, exif-reader, vitest – Begründungen in architecture.md.

## Urteil Tribunal P4–P6 (2026-08-29) – verbindlich für die Implementierung

Perspektiven: Design-Treue, Accessibility/Interaktion, Nuxt-Architektur. Bei Widersprüchen entschieden wie folgt.

**Routing & Zustand**
- Tag-Filter als **Pfadrouten** `app/pages/galerie/[[tag]].vue` (`/galerie`, `/galerie/segeln`) statt `?tag=` (Abweichung von Spec/PLAN §6 → architecture.md): kein Hydration-Mismatch, funktioniert ohne JS, prerendert, `aria-current="page"` wahr. Unbekannter Tag → 404 (`createError fatal`). Client-Middleware schreibt `/galerie?tag=x` → `/galerie/x` um.
- Detailseite: Tag-Kontext als weicher Zustand `?tag=` (Prev/Next innerhalb der Filterung, Zurück-Link → `/galerie/<tag>`). SSR rendert ungefilterte Nachbarn, nach Hydration korrigiert (`hydrated`-Flag via onMounted; `import.meta.client` reicht NICHT). Canonical ohne Query.
- Lightbox-URL `?foto=<slug>` über vue-router: Öffnen `push`, Blättern `replace`, Schließen genau ein `back()` (nur wenn selbst gepusht). Kein Hash, kein rohes pushState.
- `nitro.prerender`: `crawlLinks: true`, `failOnError: true`, `routes: ['/', '/sitemap.xml', ...photoRoutes()]` (fs-Read von app/data/photos.index.json mit Warnung wenn fehlt), `ignore: [/\?/]`.
- Sidebar-Inhalt route-gesteuert: `definePageMeta({ aside: 'gallery' | 'photo' })` + `experimental.extraPageMetaExtractionKeys: ['aside']` + `app/types/page-meta.d.ts`; Layout rendert `<TagFilter>`/`<PhotoAside>` in Slot `#aside`, Detail-Fuß in Slot `#asideFoot`. KEIN Teleport (wird im SSG verworfen), KEIN useState.
- Index: `import raw from '~/data/photos.index.json'` im Modul-Scope von `usePhotos.ts`, EIN `as unknown as PhotoIndex`-Cast; kein zod im Client. Reine Logik in `shared/utils/{photos,img,tags}.ts` (sortPhotos, filterByTag mit Spec-Fallback, neighbours zyklisch, tagCounts, parseTag, imgUrl, srcSet, buildSources mit variantMax). `shared/constants/` → `shared/utils/tags.ts` (nur utils/ und types/ werden auto-importiert). JPEG-Endung `.jpg` – mit P3-Ergebnis abgleichen.
- nuxt.config: `experimental.payloadExtraction: 'client'`, `defaults.nuxtLink.prefetchOn: { visibility: false, interaction: true }`, `runtimeConfig.public.siteUrl` aus `NUXT_PUBLIC_SITE_URL` (Coolify: BUILD-Variable), `titleTemplate: '%s – Moritz Späth'`. Scripts `predev`/`pretypecheck` = `pnpm build-images` (Cache macht's billig; Demo-Fallback garantiert Erfolg).
- Sitemap `server/routes/sitemap.xml.ts` mit `setHeader content-type application/xml` (sonst landet sie als sitemap.xml/index.html), Image-Extension, lastmod = date. robots.txt → Sitemap (P7).

**Accessibility (Ziel Lighthouse 100)**
- `--color-text-faint` #5E6874 = 3,52:1 → NICHT AA bei 10 px. Arbeitsannahme: Wert im Projekt-Block auf **#767F8B** (4,9:1) anheben; Frage an Moritz in OFFEN.md (Alternative: auf muted kollabieren).
- Landmarks: Sidebar = `<header>` (nicht aside), Fuß = `<div>` (kein footer in header), jede `<nav>` mit aria-label (Hauptnavigation / Nach Motiv filtern / Rechtliches / Foto-Navigation), genau ein `<main id="inhalt" tabindex="-1">`, Skip-Link + `<NuxtRouteAnnouncer>` in app.vue, ein `<h1>` pro Seite (Wortmarke ist Link).
- Kachel = `<a href="/foto/…">` mit modifier-sicherer Click-Interception → Lightbox; `alt = title` auf `<img>` (Prop `alt` required), Overlay-Caption `aria-hidden` (ein zugänglicher Name). Fokusring nach innen (`outline-offset:-4px` + dunkles inset-Band). Kein aria-label auf a-Vorfahren.
- Zähler „03 / 14": sichtbarer Span `aria-hidden` + `.sr-only` „Bild 3 von 14" – NIE aria-label auf p/span. Pfeile ←/→ `aria-hidden` + sr-only-Text. Lightbox-Buttons ≥44×44, Glyph aria-hidden + sr-only. `useId()` für aria-labelledby.
- target-size: Legal-Links vertikal, min-height 24 px; Filter-Padding 8 px.
- Reduced motion: `transition-duration: .01ms` statt none (+ animation-*, scroll-behavior), LQIP-Blur unter reduce ganz aus.
- Pfeiltasten auf Detailseite mit Wächtern (Modifier, Eingabefelder, offener Dialog); nicht auf der Galerie. `rel=prev/next` mitnehmen, Linktext mit sr-only-Titel.
- Optionales YAML-Feld `alt` (Fallback title) – Schema in P4 ergänzen, durch Index reichen.
